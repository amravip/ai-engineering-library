# AI Engineering Library: reader website

The reader website for the AI Engineering Library by Ravi Pal. It is built with
[Astro](https://astro.build) and [Starlight](https://starlight.astro.build), and it is
static: there is no backend, no database, no login, no analytics and no AI tutor.
Search is Starlight's built-in Pagefind, and code blocks use Expressive Code.

## Quick start

Requires Node.js 22.23.4 or newer (Astro's engine requirement). CI uses Node 24 LTS.

```bash
cd website
npm ci          # installs the exact versions in package-lock.json
npm run build   # writes dist/
npm run preview # serves dist/ at http://localhost:4321
npm run check   # build, then the link and metadata checks
```

Pinned versions: `@astrojs/starlight` 0.42.8 and `astro` 7.4.5 (peer range `astro ^7.2.10`,
satisfied). `js-yaml` 4.3.2 reads `books.yaml`. `puppeteer-core` and `axe-core` are dev-only tools for
`npm run qa:screens`.

## Content model

`books.yaml` holds every book's metadata: slug, volume number, title, subtitle (only where
the spec or the book states one), industry, project, difficulty, description, learning
outcomes and the `online` flag. The landing-page descriptions must match it exactly;
`npm run check:meta` checks this.

Only Applied AI Engineering is `online: true`. Its reading pages come from the private
authoring workspace, not from this repository.

## Generated book content

The export script lives in the private authoring workspace, not in this repository:

```text
D:\AI-Projects\AI Books\library\publishing\export_web.py
```

It reads `books.yaml` and the canonical manuscript, and writes:

- `src/content/docs/<slug>/` pages: one per chapter, plus the preface, How to Use the Code,
  Appendix A (Setup and Reproducibility) and the glossary. Appendices B and C and the
  references file are not exported.
- `public/books/<slug>/figures/` and the two cover images.
- `.generated/<slug>.json`, a manifest, so a re-run deletes stale files.

Listing and output blocks keep their code verbatim and gain a title, such as
`Listing 1.1 · examples/pizza_bot/model.py`. Figures show a visible caption, and "Chapter N"
mentions in prose link to that chapter. Each chapter ends with a generated "Related chapters"
list. Re-running the export gives byte-identical output. It was checked by hashing the output
of two consecutive runs.

```bash
# from the private workspace, with its publishing virtual environment
library/publishing/.venv-pub/Scripts/python.exe library/publishing/export_web.py
library/publishing/.venv-pub/Scripts/python.exe library/publishing/export_web.py --check
```

`--check` fails when a listing or output block differs from the manuscript, when a manuscript
H2 section is missing from its page, or when a file on disk differs from a fresh export.

The site builds cleanly without the generated content (CI does exactly that). In that state
the Applied card and landing page say that reading online is not available yet, and no link
points to a missing page.

## Publishing a book (requires the author's explicit authorisation)

Nothing in this repository is published automatically. To put a book online:

1. Confirm the author has authorised publication of that book.
2. In the private workspace, set `online: true` for the book in `website/books.yaml`
   (the export reads this file), then run `export_web.py`.
3. In `website/.gitignore`, delete that book's generated lines (the two lines under
   "Generated book content"), so its pages and figures can be committed.
4. Run `npm run check`, then commit and push. Nothing here deploys by itself.

## Repository and site settings

- `site.config.mjs`, `REPO_URL`: the public GitHub repository URL. It is empty, so every
  repository link is hidden on reader pages. Set it when the author decides the address.
- `SITE_URL` (environment variable): the public site address for the sitemap. It defaults to
  `http://localhost:4321`. Set it in the deployment environment.

## Checks

```bash
npm run build && npm run check:links && npm run check:meta
```

`check:links` verifies every internal `href` and `src` and every `#fragment` in `dist/`
(1,674 references in the full build). `check:meta` verifies that every page has a title and a
description, has one h1 and no skipped heading levels, that every image has an alt attribute,
that the sitemap exists, that the Pagefind index exists, and that landing descriptions match
`books.yaml`. CI runs both.

`npm run qa:screens` (dev only) takes full-page screenshots at 1280 and 390 px, runs axe-core
for WCAG 2.0 and 2.1 A and AA rules, checks for horizontal scrolling on phones, and captures a
search result. Set `QA_OUT` for the screenshot folder and `CHROME_PATH` for Chrome.

## Cloudflare Pages

Create a Git-connected Pages project. Settings:

| Setting | Value |
|---|---|
| Root directory | `website` |
| Install command | `npm ci` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Environment variable | `NODE_VERSION` = `24` |
| Environment variable | `SITE_URL` (optional): overrides the default address, `https://ai-engineering-library.pages.dev` |

Set the install command to `npm ci` explicitly, so the committed lock file is used. Nothing in
the repository creates or changes a Cloudflare project.

## Decisions for the author

Decided on 2026-11-08:

- The repository is `https://github.com/amravip/ai-engineering-library`. It is private, so
  `REPO_URL` stays empty and the site shows no repository links until it is made public.
- The site is deployed by Cloudflare Pages (Git-connected, project `ai-engineering-library`) at
  `https://ai-engineering-library.pages.dev`, which is the default `SITE_URL`.
- Applied AI Engineering stays private until release: `online: false` in `books.yaml`. To
  preview it locally, set it to `true`, run the export and build, and set it back. Its
  generated pages stay in `.gitignore` either way.
- Learning order: the site lists the books in volume order and says readers may take them in
  any order, because each book stands on its own. Applied AI Engineering is the suggested start
  for newcomers.
- Appendices B (data files) and C (complete source) are exported with the other back matter,
  so "Appendix A/B/C/D" in the text links to the right page. They are generated from the real
  project files, like the printed appendices. (The companion repository holds only one chapter
  checkpoint so far, so it could not stand in for Appendix C.)
- Fonts are WOFF2, converted losslessly from the variable TrueType files (3.1 MB to 1.2 MB, all
  glyphs kept). No subsetting, so every character the books use still renders.
- Plain-text blocks (data files, program output) wrap with a hanging indent so they read well
  on a phone. Python blocks never wrap, so indentation stays unambiguous.
- Difficulty: Introductory for book 1; Intermediate for books 2, 3, 4, 5, 8 and 12; Advanced
  for books 6, 7, 9, 10 and 11.
- Licence: the code is MIT (`LICENSE` at the repository root). Every page's footer says the
  book text is © Ravi Pal, all rights reserved, and the code is MIT.
- How to Use the Code no longer talks about "the repository"; it describes the book's folder
  that Chapter 1 asks readers to create.
- Descriptions and outcomes for books 2 to 12 stay as they are until each book's plan is
  written, then they are confirmed against it.

Still open:

- Subtitle for AI Harness Engineering: "Building Reliable Execution Environments for AI
  Agents", from the spec's naming example in §2.
- Cover and figure files are generated, so they are gitignored with the pages. The homepage
  card falls back to the typographic card when the real cover is absent.
- The site is light only. Starlight's theme switch is replaced with an empty component.
- Pages without a description in the manuscript fall back to the opening paragraph.

After changing `astro.config.mjs` (for example the code-block settings), delete `.astro/` and
`node_modules/.astro/` before building. Astro caches rendered Markdown there and otherwise
serves the old output.

## Known manuscript rendering notes

The manuscript is not changed. These render as written:

- Chapter 8 contains an HTML comment, `<!-- illustrative -->`. Readers do not see it.
- Starlight's build reports two warnings: a missing `i18n` collection (no translations are
  configured) and a missing content entry for the 404 page. Both come from Starlight's default
  setup and do not affect output.
- Pagefind returns one result for a nonsense query, because it matches fuzzily. "Margherita"
  returns 20 results when the Applied pages are exported.
